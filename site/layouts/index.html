Egghead

A record-store-first multi-agent system — plain markdown as the substrate, agents as participants in the graph.

{{/* ───────────── EDITOR'S NOTE ───────────── */}}

Editor's Note

This page describes a small system that treats its own records as the durable institution, and its agents as staff passing through. It is best read top to bottom, like the opening pages of a reference volume.

{{/* ───────────── § 1 — ESSAY ───────────── */}}

§ 1 The Thesis

Egghead is built on an unfashionable conviction — that the records an organization produces are the institution, and the agents that write them are only its staff. In software terms: the knowledge graph outlives any one session, any one model, any one implementation. Sessions come and go. The store persists.

Records live as plain markdown files on disk. They have optional frontmatter, they link to each other with wikilinks, and they are indexed into a rebuildable SQLite catalog for search. Nothing in this stack is load-bearing in a way that a grep and a text editor could not reconstruct. That is the point.

Agents are themselves records — class: agent, with a body that serves as the system prompt and frontmatter that configures the model and capabilities. They collaborate through a shared transcript, self-selecting via @-mentions and yielding with /pass.

{{/* ───────────── § 2 — ARCHITECTURE ───────────── */}}

§ 2 Architecture

Two supervision strategies, stacked. The record store speaks first — index and watcher come up before any agent is allowed to breathe. The agent layer sits above, and any failure there stays there. 

Egghead.Supervisor (one_for_one)
├── Phoenix.PubSub
├── RecordSupervisor (rest_for_one)
│   ├── Index          — SQLite, derived & rebuildable
│   └── RecordStore    — file watcher, parser, write barrier
└── Agent.LayerSupervisor (rest_for_one)
    ├── LLM.Registry   — multi-provider, env-var detection
    ├── Chat.Coordinator
    └── Agent.Supervisor
        ├── index      — built-in store agent
        └── agents/*   — records with class: agent
{{/* ───────────── § 3 — INTERFACES ───────────── */}}

§ 3 Interfaces

One binary, three mouths. A text-mode interface for the terminal, a Phoenix web application for the browser, and an MCP server speaking the model context protocol over both stdio and HTTP.

egghead
Launch the TUI. Records mode by default; /chat opens a shared transcript with your agents.
egghead serve
Start the web application and MCP HTTP endpoint. Read the store from a browser; wire it to an editor.
egghead mcp
Speak MCP over stdio, for editor integrations. Fifteen tools: search, get, list, create, links, backlinks, prompt, consult.
egghead llm add
Configure a provider. Anthropic, OpenAI, Gemini, Groq, Ollama. Model IDs are provider/model.
{{/* ───────────── § 4 — THE RECORD ───────────── */}}

§ 4 The Record

A record is a markdown file. It may have frontmatter. It may contain wikilinks, tables, footnotes, task lists. It is indexed into an SQLite catalog that is derived and rebuildable; delete the catalog and the truth remains.
